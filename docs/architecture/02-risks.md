# 02 — Architectural & Production Risk Register

Date: 2026-11-16
Phase: **Phase 0 (Audit & Plan Only)**

| ID | Severity | Domain | Evidence (Verified Paths & Symbols) | Risk / Failure Mode at Scale | Required Mitigation & Verification Gate |
|---|---|---|---|---|---|
| **R1** | **Critical** | World Data / Scaling | `src/data/ward.ts`, `src/data/villages/index.ts`, `src/components/regionAssets.ts`, `src/game/collision.ts`, `scripts/auditMapData.mjs` | Eager TypeScript barrels import all 11 regions (`5,862` features, `4.13 MiB` raw data) into the main JS chunk and build global spatial/label/traffic tables at startup. Scaling to thousands of Myanmar villages will exhaust WebView JS heap (`OOM`), spike parse latency, and fail Android cold start. | Migrate remaining legacy regions (`myothar` center/Area 1, `kanbale`, `natmyaung`, etc.) to `mapTileStore.ts` versioned spatial chunks (Manifest v2 + content hashes) with paired collision/ground/label release lifecycle (`Phase 3`). |
| **R2** | **Critical** | Security / Authority | `src/game/mapPermissions.ts` (`getStoredMapRole()` defaults `'admin'`), `server/TownPresenceRoom.ts` (guest `onAuth`), `shared/network.ts` (v1 presence-only) | Zero server authentication, client-trusted admin role (`?role=admin`), client-local saves (`mm-region-game-save-v1`), and client-only movement/ghost/map edits. Adding multiplayer combat, war, inventory, or market listings on this model enables trivial cheating, duping, negative-price/quantity tampering, and griefing. | Enforce signed server auth tokens, server-authoritative state ownership on Colyseus rooms + DB APIs, reject client prices/stock/hit claims, and isolate offline single-player saves from online economic/war authority (`Phase 1`, `Phase 5`, `Phase 6`). |
| **R3** | **Critical** | Spatial Precision / Coordinates | `src/game/mapProjection.ts` (per-village compressed scales), `src/game/locationDetect.ts`, `src/components/StreamedWorld.tsx` | All coordinates live directly in scene world space without camera-relative floating-origin rebasing. Across township/country scales (hundreds of kilometers), 32-bit WebGL vertex/matrix floats suffer visible jitter, z-fighting, shadow acne, and collision drift. Furthermore, legacy villages use varying compressed projection scales. | Preserve legacy compressed calibration via explicit region metadata adapters (`MapProjection` CRS metadata), define a global Myanmar planar/geodetic chunk coordinate contract (`Phase 1`), and implement camera-relative Floating Origin in `renderer-three` (`Phase 3`). |
| **R4** | **High** | 3D Assets & Android Memory | `src/assets/boy.glb` (3.80 MB), `girl.glb` (8.50 MB), `public/models/ghost-woman.glb` (3.75 MB), `canolia-character.glb` (2.15 MB), `boy t post.glb` / `girl (1).glb` root duplicates, `artifacts/blender-character/*.blend`, `.gitignore` (no LFS/mesh compression), `src/components/GlbHuman.tsx` | Built `dist/` is ~27.5 MiB (`28,828,799` B) and synced Android bundle is ~27.5 MiB (`28,875,067` B) before adding a single new NPC or building GLB. Zero Draco/Meshopt/KTX2 compression, zero GPU LOD chains, raw `.glb`/`.blend` files duplicated in ordinary Git history, and runtime texture downscaling (`clampGltfTextures`) spikes mobile CPU/RAM on startup. Individual cloned `SkinnedMesh` rigs per NPC will overwhelm draw calls in crowds. | Establish Git LFS / artifact storage for `.blend`/raw sources, build deterministic headless Blender + `gltf-transform` (Meshopt/Draco/KTX2) pipeline (`Phase 2`), separate `AssetDefinition` from placements (`Phase 1`), and batch/LOD crowd characters (`Phase 2`, `Phase 4`, `Phase 7`). |
| **R5** | **High** | Economy / Legal / Data Integrity | `src/game/subscriptionShop.ts`, `src/services/onlineServices.ts` (no backend DB, ledger, inventory, or order tables exist anywhere in repo) | Any naive implementation of marketplaces, shops, or delivery using REST PATCHes or client counts risks race conditions (double-spending stock, duplicate deliveries, split-brain between order payment and wallet debit) and mixes virtual game currency with regulated real-money flows. | Implement PostgreSQL ACID transactions (`SELECT ... FOR UPDATE` / conditional updates), idempotency keys, append-only ledger entries, snapshot pricing on order creation, transactional outbox, and strict firewall between virtual coins and external real-money PSP checkout (`Phase 6`). |
| **R6** | **High** | Mobile Runtime Perf & Monoliths | `android/app/build.gradle` (`minifyEnabled false`), `src/components/FrameBudget.tsx`, `src/components/StaticBatch.tsx`, `src/main.tsx`, `src/components/AssetLibraryPage.tsx` (3,746 LOC) | Single monolithic JS chunk (`main-*.js` > 2.6 MB unminified/bundled), non-instanced GLB scenery, synchronous `computeObstacles` / `spatialIndex` startup sweeps, per-frame `scene.traverse` / ground queries on mobile WebView, and `minifyEnabled false` in Android Gradle release config (`proguard` unused, native WebView metrics `not measured` on physical hardware). | Add Android benchmark harness on physical devices (`Phase 4`), split `AssetLibraryPage` / admin studio off the core game bundle (`Phase 3/4`), enable GPU instancing + LODs cleanly (`Phase 2/3`), and keep WebGL draw calls / triangle counts budgeted per tier. |
| **R7** | **Medium** | Backward Compatibility & Offline Saves | `src/game/gameSave.ts` (`version: 1`), `src/game/worldLayout.ts` (`version: 1`), `src/game/editorRegions.ts`, `src/game/customAssets.ts` (max 200 items), `src/game/playerHomeProtection.ts` | User-created villages, modified authored buildings (`sourceSnapshot`), custom AI assets, and player Home Safe Zone polygons live in `localStorage` without server backup or multi-version schema migrators. Cache clear or OTA storage corruption loses user creations; schema changes risk breaking saved layouts. | Add versioned migration adapters (`Phase 1`) preserving every existing `assetId`, GeoJSON coordinate, `sourceSnapshot`, and `PLAYER_HOME_REFERENCE` / safe-zone polygon invariant; back up user assets/layouts cleanly before any IndexedDB/SQLite upgrade (`Phase 4`). |
| **R8** | **Medium** | Android OTA & Capacitor Boundaries | `src/services/otaUpdater.ts`, `src/services/assetCacheManager.ts` (128 MiB limit), `src/services/offlineAssetResolver.ts`, `capacitor.config.ts`, `scripts/classifyGitChanges.mjs` | Packing thousands of future regional GLBs inside a single OTA bundle/asset manifest or `128 MiB` Cache API quota will cause OTA failures, slow cellular downloads, and cache evictions breaking offline startup. Upgrading Capacitor plugins or Android permissions via OTA fails silently without native APK release. | Keep `@capgo/capacitor-updater` strictly for compatible core web shell; transition bulk world/character assets into **region/character asset packs** fetched on demand or pinned by player selection, enforcing `minNativeVersion`/`androidVersionCode` compatibility (`Phase 4`). |
